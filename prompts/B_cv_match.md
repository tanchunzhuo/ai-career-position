# prompts/B_cv_match.md — Block B CV 匹配度

## 目标
计算用户简历 vs JD 的匹配度（百分比 + 缺失项清单），并诚实指出**哪些缺口不能靠造假补**。

## 步骤
1. 读取 `workspace/cv.md` 与 JD 关键词；
2. 提取 JD 高频关键技能词（技术栈、工具、方法论、行业术语、软素质）；
3. 逐项对照简历，分三类：
   - **✅ 已覆盖**：简历有对应证据（技能/经历/成果）；
   - **🟡 可短期补**：如某个工具/证书，几周内能学、能补（且补了真实有效）；
   - **🔴 硬缺口**：学历/年限/硬性证书/特定行业经验——**这些不要硬凑，避免造假**；
   - **🟢 同义不同表述**：能力其实有，但简历用了别的词，ATS 可能漏掉——**这是关键词优化点，不是造假**。
4. 计算匹配度百分比（按权重：硬性要求 60% + 加分项 40%，给出算法说明，允许 ±5% 区间）；
5. 输出 Top 5 需强化点 + Top 3 不可伪造的硬缺口。

## 输出格式
```
【匹配度】72%（硬性要求 13/18，加分项 7/10）

【Top 5 需强化点】按提升性价比排序，每条给"改简历的具体动作"（不是空话）

【Top 3 硬缺口】（红框提示：不要造假，要么用真实经历绕开，要么考虑放弃该岗）
1. 学历：JD 要求硕士，你是本科——除非 JD 写明"优秀本科可放宽"，否则正面承认
2. 年限：……
3. 证书：……

【关键词同义优化】JD 说 X，你简历写 Y → 建议统一表述为 X（真实能力范围内的措辞调整）
```

## 纪律
- **只做真实经历的准确呈现**：不编造经历/技能/证书/年限/在职时间；
- 若用户要求伪造（如编造大厂经历、虚报年限），明确拒绝并解释背调风险；
- 方向校验：若用户 `profile.yml` 有雷达锁定的方向，标注"该 JD 是否在你选定的交集坐标内"——偏离方向即使匹配度高也要提示（例：坐标是"医疗 AI 落地"，JD 是"通用互联网运营"，匹配度高但方向偏移）。
