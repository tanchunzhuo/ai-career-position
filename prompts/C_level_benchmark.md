# prompts/C_level_benchmark.md — Block C 职级对标

## 目标
把 JD 里的职级线索换算成**市场上可理解的对标**，帮用户判断：是否被高职级低聘、低职级高挂、以及该职级的市场年限预期。

## 步骤
1. 从 JD 提取职级线索：`资深/专家/高级/架构师/主管/P6/P7/2-2/T3.1/13级` 等；
2. 查 `data/levels.yml`，给出：
   - **对标矩阵**：该职级 ≈ 阿里 P几 / 字节几级 / 腾讯几级 / 华为几级；
   - **典型年限范围**：该职级在市场上通常对应几年经验（帮用户判断自己是否被压级）；
   - **典型总包区间**（引用数据带来源时点）；
3. 分析**晋升与跳槽涨幅预期**：
   - 跳槽通常 20–30% 涨幅；
   - **平级/降级跳预警**：什么情况下可以接受（换赛道、进平台、拿期权、避坑）；
   - 内部晋升 vs 跳槽定级的差距；
4. 若 JD 无职级信息，按职责/年限/面试轮次倒推，并标"推断"。

## 输出格式
```
【职级线索】JD 出现"资深工程师，5 年+"
【对标】≈ 阿里 P6–P7 / 字节 2-1~2-2 / 腾讯 8–9 级 / 华为 15–16 级（来源：levels.yml，时点：2026-08）
【市场年限预期】P6：3–5 年；P7：5–8 年——你 6 年经验，对标合理
【总包区间】约 50–90 万/年（C级数据，仅供参考）
【跳槽涨幅】你当前 45 万 → 跳槽合理预期 20–30% 即 54–58 万；若对方给到 40 万以下 = 变相降级，预警
【风险点】JD 用"资深"却给"专员"薪酬档；或 JD 要求 P7 能力但预算只有 P6 —— 提示在 HR 面确认职级定级口径
```

## 纪律
- 职级对标数据来自社区（C 级），**必须标注"仅供参考 + 时点"**；各厂内部调整（如字节 2025 年职级体系调整）以最新 `data/levels.yml` 为准；
- 不替用户下结论"这个职级配不上你"，只给"市场通常如何"的参照 + 建议确认的问题。
