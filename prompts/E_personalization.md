# prompts/E_personalization.md — Block E 个性化建议

## 目标
把 A–D 的结论翻译成**针对"这个人"的下一步动作**，而不是通用建议。

## 步骤
1. 读取 `workspace/profile.yml`：身份（社招/校招/转行/35+）、城市、期望、红线、雷达锁定方向；
2. **简历修改方向**（基于 B/D 结果）：
   - 应强化哪些项目与关键词（真实经历范围内）；
   - 调整哪段经历顺序（把最匹配 JD 的经历前置）；
   - 量化动作：把"负责 XX"改成"XX，规模 Y，结果 Z%"（真实数字，不编造）；
3. **投递策略**（渠道优先级）：
   - 内推 > 猎头 > 官网投递 > 平台海投；
   - 帮用户起草内推消息/自荐信（外企/港澳岗可生成求职信；**国内普通岗不生成 cover letter**，用户可按需）；给 Boss 打招呼话术（避免被系统判垃圾消息）；
4. **身份差异化策略**：
   - **校招**：内推/牛客内推码、官网网申节奏、笔试准备、实习转正路径；
   - **转行**：用"可迁移内核"包装真实经历、小作品/案例集、接受降薪的心理建设与谈判口径；
   - **35+**：把经验深度/管理/行业资源/责任能力作为定价资产；简历突出"能扛事、能落地、能带人"；提示延迟退休下长期职涯规划（2025 年起男 60→63 渐进）；避免在简历里暴露年龄劣势的无谓信息；
   - **在职跳槽**：在职保密（简历注意别让现公司知道）、背调风险、竞业限制核验（查现合同是否签竞业、范围是否覆盖目标公司）。

## 输出格式
```
【简历动作】3–5 条，每条 = 改哪里 + 怎么改 + 为什么（例：把"负责数据报表"改为"搭建 3 套自动化报表，节省 40% 周工时"——若数字真实）

【投递动作】
- 首选渠道：内推（3 天内找到 2 位内推人，话术如下）
- 内推消息模板：……
- Boss 打招呼模板：……

【身份专项】（校招/转行/35+/在职 择一展开）

【本 JD 专属提醒】如：JD 要求 XX，与你雷达方向偏 Y，注意权衡
```

## 纪律
- 所有简历修改建议以"真实经历"为前提，涉及数字/成果时先问用户确认数字是否真实；
- 不给"海投 100 家"式的建议——本工具反对海投，主张精准投递。
