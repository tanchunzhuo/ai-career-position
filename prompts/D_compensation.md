# prompts/D_compensation.md — Block D 中国薪酬调研与总包拆解

> 这是中国用户最关心、最容易被坑的模块。目标：把"招聘广告口径"拆成"真实总包"，给谈判锚点。

## 步骤

### 1. 中式薪资解析（必须能处理）
- 格式：`25-40K×15薪` / `30K·15薪` / `20-35K·14薪` / `30K+期权` / `18-30K·13薪+绩效` / `面议` / `8-12K（底薪4K+绩效）` / 外企 `25-40K·13months+RSU`；
- 提取：月薪区间、薪资本数、绩效占比、是否含期权/股票、是否"底薪+提成"；
- 计算**年化现金区间**（最低/最高薪资本数分别算），并明确标注：**"这是招聘广告口径，不等于到手"**；
- 检测薪资红旗：仅写"面议"（提示通常偏低/要压价）；绩效占比过高（基本薪资 <70%）；试用期打折 >20%；"底薪+高提成"结构。

### 2. 市场对标（查 `data/salary.yml`）
- 岗位 × 城市 × 职级 → P25/P50/P75 分位数；
- 每条数据标注来源（看准/脉脉/OfferShow/各厂薪酬报告）和**数据时点**；
- 对标用户期望薪资 / JD 广告薪资 / 市场 P50，标出**缺口**（借鉴 career-ops 的 salary-gap 思路）。

### 3. 总包拆解（给用户"要追问 HR 的问题清单"）
- 月薪 × **实际薪资本数**（问"去年团队实际发了几个月"，而非 HR 口头的 15/16 薪）；
- 绩效/年终奖：占比、考核分布、是否写进合同；
- 签字费、留任奖金及绑定条件；
- 股票/期权：RSU vs 期权、**归属期（vesting）、行权价、离职后处理、cliff**；
- 补贴（餐/房/通讯/交通/加班）、补充公积金、企业年金；
- **五险一金缴纳基数**（按实际工资还是最低基数——大坑，直接影响到手和未来养老金）、社保城市（与落户/买房/医保挂钩）、个税；
- 外企岗：是否有 RSU/ESPP、年假与弹性办公差异。

### 4. 输出
```
【广告口径年化】25-40K×15薪 ≈ 37.5–60 万/年（税前，广告口径，不等于到手）

【市场对标】(来源：salary.yml；时点 2026-08；C级仅供参考)
  北京·算法工程师·P6：P25≈40万 / P50≈55万 / P75≈70万
  你的期望 50 万 → 处于 P50 附近，合理

【总包拆解】按 40K×15 估算到手：月扣五险一金+个税 ≈ ……（给估算公式，不精确承诺）

【需向 HR 确认的问题清单】
1. 去年团队实际发了几个月薪？
2. 年终奖/绩效占比多少？考核怎么分布？写进合同吗？
3. 五险一金按什么基数缴纳？社保城市是哪里？
4. 股票/期权：归属期多久？cliff？离职未归属部分怎么办？
5. 试用期多久、工资打几折？

【谈判锚点】基于 P50 与你的底线：建议先报区间不报单点，锚定 55–60 万总包
```

## 纪律
- 所有数字带来源+时点；分位数给不出就标"数据不足，待核验"；
- 估算到手时说明：按当前个税/社保规则粗算，实际以 HR 确认与社保局为准；
- 不替用户做薪资决定，只给锚点、底线、话术（联动 `negotiation.md`）。
