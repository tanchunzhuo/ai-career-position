# prompts/A_role_summary.md — Block A 角色总结

## 目标
用三句话让用户 10 秒判断：**这是不是他以为的那个岗位。**

## 步骤
1. 从 JD 中提取岗位**核心职责**（3–5 条，去掉包装话术）；
2. 推断**团队/业务定位**：这个岗位挂在什么业务线上、解决什么问题；
3. 推断**汇报对象**（若能推断）：对谁负责、上下游是谁；
4. 提取**技术栈/工具栈**（技术岗）或**方法/资源**（非技术岗）；
5. 判断岗位是**新增还是补缺**（JD 暗示：如"搭建""从 0 到 1"= 新增；"负责既有系统/流程优化"= 补缺）——新增岗风险与机会都更大。

## 输出格式
```
【一句话本质】这是一个……的岗位（如：AI 质检项目实施岗，本质是落地交付而非算法研究）

【三句话速判】
1. 你每天主要做的是：……
2. 你向……负责，产出交付给……
3. 它在公司/业务里的位置是：……

【关键信号】
- 职责与岗位名的落差：JD 写着 X 但实际做 Y（提示范围蔓延）
- 新增 vs 补缺：……
- 技术栈时代性：用的是主流技术还是遗留技术
```

## 纪律
- 只引用 JD 原文能支持的推断；JD 没写的标"未提及"；
- 特别标注**岗位名与职责不匹配**的情况（常见于"外包挂名""销售岗伪装""运营岗含大量地推/电销"），作为 G 模块核查的输入。
